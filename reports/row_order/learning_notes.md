# 学习笔记：训练集行顺序能当作时间吗？

本步骤想解决一个验证策略问题：如果 `train.csv` 从上到下按放款时间排列，
拿后面的贷款做验证集会比随机划分更像预测未来数据。但匿名数据没有给出真实
放款日期，因此**不能看见行号就假定它是时间**。我们需要先找支持或反对这一
假设的证据。可运行代码在 `scripts/check_train_row_order.py`，具体指标在
`row_order_report.md`。

## 一、先确认“行号”究竟是什么

脚本逐行读取原始 CSV，只检查第一列 `id`：

```python
for physical_line, line in enumerate(source, start=1):
    comma = line.find(b",")
    if line[:comma] != str(physical_line - 1).encode("ascii"):
        mismatches += 1
```

`physical_line - 1` 是从 0 开始的数据行号。训练集 688,998 行、测试集
36,324 行，都没有不一致。之前转换出的 Parquet 行序也与训练 `id` 完全一致。
因此本项目可以用 `id` 表示**当前文件中的位置**，但它不能因此被解释为
放款日期：测试集的 `id` 也从 0 重新开始，并不是接在训练集最后一个 ID 后面。

## 二、把训练行顺序切成十个连续区段

核心 SQL 是：

```sql
SELECT CAST(FLOOR(id * 10.0 / 688998) AS INTEGER) + 1 AS row_decile,
       AVG(CAST(label AS DOUBLE)) AS repayment_rate,
       MEDIAN(feature_492) AS feature_492_median,
       AVG(CAST(feature_1039 IS NULL AS DOUBLE)) AS feature_1039_missing_rate
FROM processed_train
GROUP BY 1
ORDER BY 1;
```

这里的 `row_decile` 是第几段，1 是文件开头、10 是文件末尾。
因为竞赛的 `label=1` 表示还款，0 表示违约，二元标签的平均值刚好等于还款率。
`feature_1039 IS NULL` 对缺失行是 1、非缺失行是 0，平均值就是缺失率。

如果行号真能代表时间，我们至少希望看到某些与训练/测试漂移有关的特征
沿行号有方向性变化。例如测试集 `feature_492` 中位数是 8.8670，训练集
越靠后的区段若逐渐向它靠近，才可能支持这一想法。实际十段的该列中位数
只有 8.1117–8.1202，第一段 8.1117，最后一段 8.1146；没有逐段靠近测试集。
还款率也仅在约 91.55%–91.79% 之间小幅波动。十段的全部数字见
`train_deciles.csv`。

## 三、Spearman 相关系数看整体单调趋势

脚本对训练集非缺失的 `feature_492` 计算：

```python
spearmanr(id_values[observed], feature_492_values[observed]).statistic
```

Spearman 衡量“行号越大时，特征值是否总体越大或越小”，范围为 -1 到 1。
结果约 **0.000219**，基本没有单调关系。它只检验这一列的单调趋势，
不能排除其他列或非单调的分段变化，因此还要做下一项全特征检验。

## 四、让模型尝试区分训练集的开头和结尾

取最前和最后各 36,324 行，组成等量的二分类实验：

```python
edge_label = np.r_[np.zeros(36_324, dtype=np.uint8),
                   np.ones(36_324, dtype=np.uint8)]
# 0 = 文件开头；1 = 文件结尾
```

输入只有 1,105 个匿名 `feature_*`，**没有 `id` 和还款 `label`**。如果把 `id`
喂给模型，它当然可以直接认出开头/结尾，那只是把答案泄露给模型，不是找到
时间相关的特征变化。贷款 `label` 则是另一个研究目标，不能混入来源特征。

脚本复用对抗验证的 LightGBM 训练函数：三折分层验证，每折内部再留 15%
数据早停；外层验证折只用于最终 AUC。这保证模型在自己没见过的行上判断
“前段还是后段”。如果 AUC 接近 0.5，说明它基本无法区分。

另一个实验把前/后标签随机打乱，但保持特征和标签数量不变：

```python
shuffled = np.random.default_rng(SEED).permutation(edge_label)
```

它是“理论上不应存在真实位置信号”的对照。实际前后段 AUC 为 **0.49774**，
随机标签对照为 **0.49909**，都在随机水平附近。0.49774 比 0.5 略低，
不代表找到反向时间轴；这个差距非常小，而且对照也会有类似的抽样波动。
这里的 AUC 预测的是行位置，**不是贷款还款预测的 AUC**。

## 五、怎样把证据转成验证策略

以上证据共同表明：**目前没有可靠理由把文件末尾直接当“未来贷款”留出**。
因此第一版还款模型可以先做随机分层验证；同时要记住之前发现的训练/测试
巨大漂移，所以随机验证成绩未必能代表官方测试集。只有获得可核验的真实
日期、批次或其他顺序字段，才应设计真正的时间留出验证。

这个结论有边界：我们没有真实时间戳，也只用两端样本进行全特征分类。
“没发现行序信号”不等于数学上证明原始记录绝无时间信息；更不能据此说
官方训练/测试没有时间差。匿名列 `feature_492` 的数值变化很强，但它在
训练集内部不随行号变化，不能据此把它命名为日期字段。

## 面试表述

> 我没有直接把 CSV 行号当作时间。先逐行核对原始文件，确认 `id` 只是各自
> 文件从 0 开始的行位置；然后按训练行号分十段看还款率和高漂移特征的分布，
> 没有发现连续趋势。`feature_492` 与行号的 Spearman 相关约 0.0002。
> 再用 1,105 个特征区分训练集最前和最后各 36,324 行，三折 AUC 约 0.4977，
> 与随机标签对照的 0.4991 相近。所以目前不把行号用作时间切分依据，
> 而以随机分层验证作基线，并明确记录它对官方测试集漂移的局限。
