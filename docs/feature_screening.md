# 缺失模式、漂移和低方差特征筛选：学习说明

本次实现使用完整训练数据。实际数值以
[结果报告](../reports/feature_screening/feature_screening_report.md)为准；训练流程在
[run_feature_screening.py](../scripts/run_feature_screening.py)。本项目 `label=1` 是还款，
所有模型的 `p_repay` 是还款概率，违约概率是 `1-p_repay`。

## 1. 为什么 LightGBM 后面还要做这一步？

LightGBM 原始基线已经能处理 NaN，整体 OOF AUC 为 0.816569。但“能处理缺失”不等于
“所有缺失相关的信息都已经充分表达”，也不等于训练与测试的缺失率差已经得到解决。
同样，高漂移、低方差、高缺失这些诊断标记不直接等于“特征没有预测价值”。

这一轮要用消融实验回答三个问题：

1. 显式增加缺失模式特征，在原生缺失路由之外是否有额外收益？
2. 删除可用性差的列或几个主要漂移列，会损失多少信息、是否改善本地效果？
3. 有没有足够接近常数、确实可以去除的列？

消融实验是控制其他配置，改变一项方案并评价结果。本轮四种方案分别与原始基线比较，
没有先把所有变更合并。可用性方案包含两种删列规则，因此其结果只能归因于整个组合。
这轮不是寻找所有可能组合的最优解。

## 2. 实验协议与上一轮有何不同？

沿用完全相同的分层五折，保留整体和既定压力组指标。每折树数固定为上一轮通过内部
早停选出并用于完整四折重训的树数：528、512、597、505、513。参数、随机种子和线程数
也保持一致。当前轮不重新早停，以比较相同模型复杂度下的特征方案。

```python
fitting = np.flatnonzero(fold_id != fold)
valid = np.flatnonzero(fold_id == fold)
rounds = baseline_meta['record']['refit_rounds']
params = base.model_params(fold, args.threads)
```

`fitting` 是当前拟合四折的行位置，`valid` 是留出折。上一轮选择该折树数时也没有使用
这条外层验证记录。复用树数不会把当前外层标签带入选择。

所有需要学习的筛选规则在当前拟合四折内计算，之后固定应用于拟合、外层验证和测试。
没有用全量标签的缺失率差选标记，没有用测试值学习填补或分箱规则。

这里有一个有意保留的区别：测试全空列和漂移候选名单，来自先前对测试协变量的无标签
诊断。这是针对已知测试分布的候选消融，不能说整轮完全没有看过测试特征。
它没有使用测试还款标签，也没有用测试值拟合还款模型。

## 3. 缺失模式是什么？

对一个特征，除了值本身，还可以记录它是否缺失：

```text
原始值：   3.2    NaN    0.0
缺失标记： 0      1      0
```

这里 0.0 是一个真实数值，其缺失标记为 0。不要把零和 NaN 混为一谈。
缺失可能描述采集流程、记录可用性或其他未知机制，在本项目中不能直接赋予业务含义。

如果某列在还款记录中缺失 10%，在违约记录中缺失 35%，两类缺失率相差 25 个百分点。
说明缺失状态与标签有关联，不说明缺失导致了违约。

## 4. 为什么缺失标记要在折内选？

当前实现会读取一列的原始缓存，但真正参与统计的是拟合行：

```python
selected = np.asarray(raw)[indices]
y = labels[indices]
missing = np.isnan(selected)

default_missing = float(missing[y == 0].mean())
repay_missing = float(missing[y == 1].mean())
gap = abs(repay_missing - default_missing)
```

`np.isnan` 返回布尔数组；布尔值求平均就是缺失比例。`y == 0` 选择违约行，`y == 1`
选择还款行。我们提前设定 `gap >= 0.10` 才增加缺失标记，不根据外层结果搜索这个阈值。

该筛选使用了还款标签，属于监督筛选。即使只是在选列，而没有训练树，使用外层标签
也会污染验证。代码因此对每个拟合四折重新统计。各折选中的标记数量可以不同。

过去 EDA 中的全训练标签缺失差，只能用于描述和形成实验想法，本轮没有直接拿它生成
统一的监督筛选名单。测试核对：修改外层特征或标签，不改变拟合行的统计和规则。

## 5. 增加了哪些缺失特征？

`missing_patterns` 保留全部 1,105 个原始特征及原始 NaN。新增：

1. 折内标签缺失差至少 0.10 的列对应的二值 `missing__feature_*`。
2. `row_missing_count`，一条记录在原始 1,105 列中缺失的列数。

```python
pieces.append(np.isnan(raw[:, self.indicators]).astype(np.float32))
pieces.append(np.isnan(raw).sum(axis=1, keepdims=True).astype(np.float32))
```

第一行只取选中的列，生成 0/1 标记。第二行对列方向求和，得到每条记录缺失数量。
`keepdims=True` 保留二维列形状，方便与原始矩阵拼接。

没有同时增加缺失比例，因为原始列数固定，比例与数量只是固定倍数关系，表达重复。
也没有把缺失值全部填成零。

原生 NaN 路由是树在当前特征节点上决定缺失走向；显式标记允许模型直接使用缺失状态，
逐行缺失数量则总结了多列共同缺失的模式。因此有可能补充信息，也可能重复已有信息、
增加复杂度或利用不稳定的采集信号。是否有收益由 OOF 决定。

## 6. 为什么测试全空或训练极高缺失列只是候选？

`availability_filter` 使用两种预先确定的规则：

- 删除测试全空 7 列：feature_364、614、648、660、805、1009、1031。
- 删除拟合四折内缺失率至少 90% 的列。

```python
reasons = {name: 'test_all_null_predeclared'
           for name in names if name in TEST_ALL_NULL}

for name in indexed.index[indexed['missing_rate'] >= 0.90]:
    reasons[name] = 'fit_missing_rate_at_least_90_percent'
```

测试全空意味着这些列在已知测试数据中无法提供数值区分。但删除它们可能改变训练中
模型使用其他特征的方式，不能直接推断 OOF 一定上升。

高缺失率也不等于无信息：少数非缺失记录、缺失状态本身可能具有预测价值。90% 是本轮
固定候选规则，不是通用最佳阈值。本轮没有按重要性或外层结果重新调整它。

JSON 计划保存每列的删除原因。该方案组合了全空与极高缺失两种处理，效果不能单独
归因为其中一种；若要分开归因，需要更多独立实验。

## 7. 漂移是什么意思？为什么不删除所有高漂移列？

漂移描述训练与测试的特征分布不同，包括数值分布和缺失比例变化。
先前对抗分类器预测数据来源，AUC 接近 1；它不是还款预测模型。

`drift_core_filter` 只删除提前声明的四列：

- feature_492、903、586：此前主要来源分类与数值漂移候选。
- feature_1039：训练/测试缺失比例差非常大的候选。

```python
reasons = {name: 'drift_candidate_predeclared'
           for name in names if name in DRIFT_CORE}
```

名单来自之前无还款标签的来源/分布诊断，不根据当前外层结果改名单。其余原始特征保留。
没有把 541 个高漂移标记列全部删除。因为分布不同与还款预测有用可以同时成立；
一个高漂移特征可能仍然提供重要信息，相关特征也可能保留相似漂移信号。

删除四列不等于消除漂移，随机 CV 也没有因此变成时间验证。feature_492 测试非缺失值
约 76.5% 超过全训练最大值，这一部分没有已知标签，训练上尾压力组不能完全模拟它。

## 8. 低方差为什么不能用同一个数值阈值筛？

方差描述一列数值相对均值的波动：

```text
Var(x) = 平均值[(x - 平均值(x))²]
Var(a*x) = a² * Var(x)
```

例如 `[1, 2, 3]` 乘以 0.001 后变成 `[0.001, 0.002, 0.003]`。顺序和信息没变，方差却
变为原来的百万分之一。树还能按相应阈值区分这些值。

匿名特征尺度不同，本轮因此不直接使用统一的原始 `VarianceThreshold(0.01)`。
标准化后所有有变化的列又大致是单位方差，也不能直接解决这种筛选问题。

本轮报告非缺失方差，但实际筛选采用尺度不敏感的近常数规则：拟合四折中至少 99.5%
的记录处于同一个观测值或缺失状态。统计基于实际模型使用的 float32 缓存。

```python
observed = selected[~missing]
unique, counts = np.unique(observed, return_counts=True)
modal_count = int(counts.max())

dominant_state_share = max(modal_count, missing_count) / len(selected)
```

`np.unique(..., return_counts=True)` 统计精确值的出现次数，最大计数对应众数。
NaN 作为另一个状态，用缺失计数与众数计数比较，再除以全部拟合行数。

若没有观测值，众数计数为零，全部 NaN 的列占比就是 1。若存在观测值，其方差只作描述。

特别注意 `[7, 7, NaN, NaN]`：非缺失方差为 0，但整个输入仍有两种状态，各占 50%，
所以不是常数输入。删除它可能损失缺失信息，当前规则会保留。

没有列达到规则时，正确结果是“不删列”。代码记录 identity 并复用完全相同的基线模型
和预测，不为完成筛选而强行删除，也不宣称训练了新的不同模型。

本轮精确核查实际发现 feature_51 与 feature_118 在各拟合四折的 float32 输入中达到规则。
这不是证明原始 DOUBLE 数据中的两列也近似常数。`precision_audit.json` 对原始训练列
与当前缓存进行对照：feature_118 的非缺失精确值个数从 3,049 变成 51，最大状态占比
从约 2.79% 变成 99.63%；feature_51 的最大状态占比从约 97.48% 变成 99.52%。
很接近的原始值在 float32 舍入后合并了。本轮所有方案沿用基线相同输入精度，因此
评价的是“当前输入精度下删列”的效果；原始高精度信息是否有价值需要单独比较输入
精度，不能用本轮删列结果代替那个实验。核查使用全训练原始列只为解释精度现象，
没有改变当前折的筛选规则。

## 9. FeatureView 怎样保证训练和预测使用同一份列规则？

每折保存 `original_features`、`kept_features`、`missing_indicators`、`output_features`、
是否增加逐行缺失数量和具体删除原因。这就是该折的 feature plan。

```python
view = FeatureView(values, plan)
test_view = FeatureView(test_values, plan)

dataset = base.make_dataset(
    view, labels, fitting, plan['output_features'], params, args.batch_rows
)
model = lgb.train(params, dataset, num_boost_round=rounds)
```

同一 plan 固定用于该模型的拟合、外层验证和测试预测。不同折的新增列可能不同，必须
分别应用各自的计划。不能把第 0 折列顺序套给第 1 折模型，也不能在测试集重新选列。

FeatureView 只在当前请求的行/批次上选择原始列、构造标记并拼接。再通过上一轮的
IndexedSequence 提供给 LightGBM。没有预先生成四份完整的大型转换矩阵。
LightGBM 分箱与直方图仍需内存；这里是减少原始矩阵复制，不是零内存训练。

id、label、fold、压力组标记都不进入特征。真实零值保留，原始 NaN 保留。

## 10. 为什么比较固定树数，而不重新早停？

这是本轮的实验控制选择。复用基线树数让比较回答“相同配置和复杂度下，特征方案是否
改善”。如果每个方案再单独选择树数，结果也可以评价，但同时包含训练长度变化。

当前结果不代表每个特征方案各自调到最优后的水平。第 2 折基线选树数时达到过预算上限，
复用 597 棵树也继承了这一限制。模型仍然从头在当前拟合四折的转换特征上重新训练，
不是在旧树后追加，也不是仅把旧模型中的列删掉。

## 11. OOF、压力组和测试提交怎么生成？

```python
oof[valid] = stored['p_repay_valid']
coverage[valid] += 1
test_score += stored['p_repay_test'] / 5
```

每条训练记录只由排除了它所在折的模型生成一次 OOF，代码检查覆盖恰好一次。不能把
五个模型对训练记录的预测全部平均，四个模型已经见过该训练记录。

测试记录没有参与任何还款模型拟合，可以平均五个模型的还款概率，按官方模板 ID 对齐。
训练/测试 ID 可能数值重叠，它们不用于连接训练标签到测试。

评价整体和既有 feature_492 上尾、feature_1039 非缺失压力组。压力组使用同一批 OOF
预测的子集，不单独训练或选阈值，组间可以重叠。组间 AP 比较需结合各组违约比例。

## 12. 哪些指标说明什么？

- 还款 ROC-AUC：排序能力，越高越好，不是准确率。
- 违约 AP：`average_precision_score(1-label, 1-p_repay)`，越高越好，关注少数类。
- log loss 与 Brier：概率预测误差，越低越好，不单独证明完美校准。
- 配对折差：同一折新方案指标减去原始基线指标，观察不同折方向是否一致。

整体 OOF AUC 由全部折外概率一次计算，不等于各折 AUC 的简单平均。
不同折模型的拟合样本重叠，五个折差不是五个完全独立实验，不据此保证统计显著性。

本轮新增缺失列在各折获得约 0.51%–1.53% 的训练分裂增益占比，但完整 OOF 没有提高。
这说明模型使用了特征，不等于特征带来了折外收益；这个占比也不是准确率贡献或因果效应。
每折 gain 汇总记录在 `missing_feature_gain_summary.csv`。

本轮根据同一套 OOF 比较方案，因此选择结果属于开发过程。不要把选择后的最好分数
包装成新的完全独立测试成绩，更不能承诺训练范围外的官方测试效果。

## 13. 为什么要保存规则与做核查？

模型需要正确列顺序，新增缺失列又是折内监督选出来的；只保存树文件不够。
本轮保存模型、每折计划、完整折内统计、来源和代码签名、预测、指标、提交与配对差。
中断恢复只复用签名一致、模型校验一致的完整折 checkpoint。

测试覆盖：外层特征/标签变化不影响规则、缩放不影响近常数筛选、保留缺失信号、NaN 与
真零语义、任意请求行顺序、分批训练/预测与普通数组一致。

产物核查再次从原始缓存计算全部折内统计、重建计划，加载全部模型复现 OOF 和测试均值，
核对固定树数、每行覆盖、指标和提交 ID。图使用全部结果计算，只承担展示职责。

## 14. 面试怎么讲？

> 我在固定 LightGBM 基线之后做了特征处理消融。缺失标记根据每个拟合四折中的标签
> 缺失率差选择，还增加了逐行缺失数量；可用性和主要漂移列作为独立候选方案评价。
> 由于匿名特征的尺度不同，我没有用统一原始方差阈值删列，而是用包含缺失状态的精确
> 近常数占比检查信息量。各方案固定基线树数和参数，比较相同五折的 OOF、压力组和
> 概率误差。每折的列规则与模型一起保存，重载能够复现预测。具体保留或放弃哪些方案，
> 我根据实际实验结果解释；随机验证与测试漂移的局限仍然存在。

追问时要能回答：为什么缺失标记选择必须在折内？为什么高漂移不等于无用？为什么
低原始方差不等于常数？为什么 observed variance 为零但缺失模式变化的列仍保留？
为什么固定树数？为什么没有列能删时不重新训练？为什么最好 OOF 仍是开发结果？

## 16. 本轮实际结论

| 方案 | 整体 OOF AUC | 违约 AP | Log loss | Brier |
| --- | ---: | ---: | ---: | ---: |
| 原始 LightGBM | 0.816569 | 0.388912 | 0.225850 | 0.062500 |
| 新增缺失标记和数量 | 0.816381 | 0.388462 | 0.225892 | 0.062506 |
| 删除测试全空和极高缺失列 | 0.816343 | 0.388955 | 0.225878 | 0.062490 |
| 删除主要漂移四列 | 0.815981 | 0.387376 | 0.226145 | 0.062586 |
| 删除近常数两列 | 0.816407 | 0.388595 | 0.225885 | 0.062504 |

按提前关注的主要指标 AUC，本轮继续保留原始 1,105 列与原生 NaN 处理方案。
可用性方案的 AP 和 Brier 略好，且 492 上尾组有小幅改善，但 AUC 略低，1039 压力组
也没有改善。其余方案也未带来整体 AUC 优势。删除漂移四列的五折 AUC 全部下降。
本轮差值总体很小，不把配对折当作独立样本保证显著性，也不宣布所有其他阈值、组合
或重新调参后的方案永远无效。

20 项单元测试通过；另外全量重算了 5,525 行折内特征统计，重建全部规则，重载 20 个
