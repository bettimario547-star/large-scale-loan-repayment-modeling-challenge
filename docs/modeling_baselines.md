# 第三步建模路线：常数预测与逻辑回归基线

这一项开始真正预测还款。实际实现是
[`scripts/run_linear_baselines.py`](../scripts/run_linear_baselines.py)，
运行结果见
[`reports/linear_baselines/linear_baselines_report.md`](../reports/linear_baselines/linear_baselines_report.md)。
两种模型沿用第二步保存的五折，训练目标始终是 **`label=1` 表示还款**。

## 1. 常数模型为什么值得做？

假设一折拟合数据有 100 笔贷款，其中 92 笔还款。常数模型给验证折每笔贷款
都预测 `p_repay=0.92`，不读取任何贷款特征。实际代码是：

```python
fit = fold_id != k
valid = fold_id == k
p_repay_constant[valid] = y[fit].mean()
```

这里均值来自拟合四折，不能从全量标签计算该折的预测。
它回答的是：“如果我只知道还款的基准比例，能做到什么程度？”

因为这一折所有概率相同，模型没有区分贷款的能力，ROC-AUC 恰好是 0.5。
按 0.5 阈值做分类，它会把所有贷款判断为还款；本项目仍能得到约 91.67%
准确率。因此高准确率可能只来自类别不平衡。

常数还为 log loss 和 Brier score 提供参照。把 0.92 改成 0.5 虽然不改变
排序能力，却改变概率误差。只有 AUC 不能评价概率是否合理。

注意：五折的均值略有差异，拼接后的常数 OOF 向量有几个不同取值，因此
整体 OOF AUC 可能略偏离 0.5。这是折间基准比例的差异，每折常数依旧没有排序能力。

## 2. 逻辑回归到底学了什么？

模型为每个标准化特征学习一个系数，再加上截距：

```text
score = intercept + coef_1*x_1 + ... + coef_1105*x_1105
p_repay = 1 / (1 + exp(-score))
```

系数正负描述其他输入固定时该特征与预测还款概率的关系；匿名特征的语义未知，
也可能互相相关，所以不能把系数解释成业务因果关系。

这里的输入只包含 `feature_1` 到 `feature_1105`；`id` 用于连接折号和提交模板，
`label` 单独作为训练目标，`fold` 和压力标记只安排验证。

训练用二分类 log loss，再加入 L2 正则，限制系数过大。固定 `C=1.0`，
不自动加类别权重。违约较少并不意味着概率基线必须使用 `class_weight='balanced'`：
改变类别权重会改变训练目标和概率的含义，需要另做实验。

## 3. 为什么先填补缺失，再标准化？

逻辑回归无法直接接受 NaN，而且这里的匿名特征数值尺度不同。
每折预处理独立完成以下操作：

1. 只在拟合四折统计每列的非缺失均值。
2. 用这个均值填补拟合、验证和测试数据中的缺失。
3. 只在填补后的拟合数据上计算每列标准差。
4. 所有数据用同一组拟合均值和标准差变换。

例如拟合数据某列为 `[2, 4, NaN]`，填补均值为 3，填补后为 `[2, 4, 3]`，
标准差按这三个值计算。验证数据即使出现 1000，也不改变均值或标准差。
均值填补的单元格标准化后是 0。

本轮采用均值填补，便于在全量宽表上精确分块统计。中位数填补、缺失指示变量、
删掉测试全空列都可在后续分别实验；本轮固定一个简单参照。
没有根据全量标签的缺失率差筛特征，也没有用测试集拟合统计量。

## 4. 数据太宽，如何完成全量逻辑回归？

训练集有 688,998 行、1,105 个特征，float64 特征矩阵本身就约 6.1 GB，
训练时还可能产生额外副本。项目实现把纯特征缓存为磁盘上的 float32 数组，
每次只操作 8,192 行。

每折先分块计算拟合统计量，生成该折标准化后的拟合矩阵。SciPy 的 L-BFGS-B
每次迭代仍计算**所有拟合样本**的损失和梯度，只是把它们分块累加。
这不是抽样训练，也不是每批更新参数的随机梯度下降。
目标与 sklearn 二分类 L2 `LogisticRegression` 一致，小型测试对照两者的预测。

这个实现是适配当前内存条件的计算方式。使用普通大小的数据时，可以直接写
`Pipeline(SimpleImputer, StandardScaler, LogisticRegression)`，遵循相同的折内拟合规则。

## 5. 怎样看结果？

每条训练记录的 OOF 概率都来自没有用过其标签的那一折模型。
结果报告同时保存每折指标和拼接后的整体指标：

| 指标 | 计算方法 | 含义 |
| --- | --- | --- |
| 还款 ROC-AUC | `roc_auc_score(label, p_repay)` | 还款与违约贷款的排序能力 |
| 违约 PR-AUC / AP | `average_precision_score(1-label, 1-p_repay)` | 少数类违约的识别能力，受违约基准率影响 |
| log loss | `log_loss(label, p_repay)` | 概率与真实结果的差距，对自信的错误惩罚较大 |
| Brier score | `mean((p_repay-label)**2)` | 概率平方误差 |
| 0.5 阈值准确率 | `accuracy_score(label, p_repay >= 0.5)` | 辅助说明类别不平衡，不能作为主要胜负依据 |

报告还使用保存的压力标记，分别评价 `feature_492` 高尾组和 `feature_1039`
非缺失组。压力组使用同一批 OOF 概率，不重新训练，也不修改第二步的阈值。
分组违约率不同，需要同时看 AUC、AP、违约率和样本量。

## 6. 测试预测与提交文件

常数测试预测使用全量训练标签的平均还款率。
逻辑回归测试预测是五折模型输出的还款概率均值。各折模型和预处理参数均保存，
没有另行全量重训。

两个本地提交文件均调用已有 `build_submission` 按测试 id 对齐官方模板，
检查行数、id 唯一性和概率范围。提交列仍为 `id,prediction`，预测含义是还款概率。
生成 CSV 不代表已经上传比赛，训练内结果也不等于官方测试成绩。

## 7. 如何复现，面试时怎么讲？

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe .\scripts\run_linear_baselines.py
.\.venv\Scripts\python.exe .\scripts\verify_linear_baselines.py
```

最后一条命令独立重算指标，重载五折模型复现测试预测，核对折表未变和两个提交文件
的 id、概率是否正确。核查结果保存在 `reports/linear_baselines/artifact_verification.json`。

可以这样描述这一项：

> 我先用每折拟合集的平均还款率建立常数基线，确认约 91.67% 的准确率可以
> 完全来自类别不平衡。再在固定五折上训练 L2 逻辑回归，每折独立做均值填补
> 和标准化，保证 id、标签及验证元数据不进入特征。由于宽表超过可用内存，
> 我使用磁盘矩阵和分块全批量损失、梯度计算，并用小数据对照 sklearn。
> 结果同时报告还款 AUC、违约 AP、概率误差和预先定义的压力组表现。
> 这给后续树模型提供公平的参照；训练与测试的强漂移仍限制这些分数的外推。
