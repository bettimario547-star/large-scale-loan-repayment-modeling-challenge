# 第三步：超参数与随机种子优化学习说明

本说明对应 `scripts/run_hyperparameter_seed_optimization.py` 的实际实现。
运行后的具体成绩、每折配置、树数和核查结果在
`reports/hyperparameter_seed_optimization/hyperparameter_seed_report.md`。

本轮已完成：20 个内部搜索模型、15 个完整四折重训模型。三种子等权集成的开发 OOF
AUC 从原基线的 **0.816569** 提高到 **0.820395**（绝对提高 **0.003825**），
违约 AP 从 **0.388912** 提高到 **0.395367**，log loss 从 **0.225850** 降到
**0.224226**，Brier 从 **0.062500** 降到 **0.062114**。集成在五个验证折的 AUC
均高于原基线，因此作为下一步开发候选；这不是官方测试成绩。

重载全部 35 个模型核查，内部、OOF 和测试预测与保存结果的最大差均为 **0.0**；
已完成的全项目测试共 **25 项通过**。三个单种子及集成本地提交文件均已生成，未上传。

## 1. 这一步解决什么问题

上一轮证明 LightGBM 比逻辑回归更适合这批数据，特征筛选实验没有带来可靠收益，
因此本轮继续使用全部 1,105 个原始匿名特征。标签 `1` 表示还款，`0` 表示违约，
模型输出始终是还款概率 `p_repay`，违约概率是 `1 - p_repay`。

本轮检查两个问题：当前树的复杂度、学习速度和正则化是否合适；固定配置在不同
建树随机抽样下是否稳定，以及平均多个模型的概率能否改善开发验证表现。
目标不是在验证集上反复尝试，直到碰巧出现最高分。

**模型参数**是训练从数据中学出来的内容，例如树使用哪个特征、在什么位置分裂、
叶子输出多少；**超参数**是训练前我们指定的规则，例如一棵树最多多少叶子、
学习率是多少、叶子最少需要多少样本。调参就是比较这些规则产生的模型。

## 2. 本轮搜索的范围

使用四组提前指定的联合配置，每一折都训练全部四组，没有根据折外分数追加候选。
这是预算有限的人工候选搜索，不是完整网格、随机搜索或 Optuna 贝叶斯优化。
Optuna 虽然已安装，这轮代码没有调用它。

| 配置 | learning_rate | num_leaves | min_data_in_leaf | lambda_l2 | feature_fraction | bagging_fraction |
|---|---:|---:|---:|---:|---:|---:|
| baseline_extended | 0.05 | 31 | 200 | 1 | 0.80 | 0.80 |
| regularized | 0.05 | 31 | 400 | 5 | 0.75 | 0.85 |
| wider | 0.05 | 63 | 300 | 5 | 0.80 | 0.80 |
| faster_rate | 0.08 | 31 | 300 | 3 | 0.80 | 0.80 |

原来的最多 600 轮提高到 900 轮，因为原基线有一折用完 600 轮预算。
`baseline_extended` 给原配置更多训练机会，所以新旧差异也包含训练预算/早停设置变化。
其他配置同时改变多个参数，结果只能说明整组配置的表现，不能据此断言某个单独参数导致涨分。

没有搜索 `max_bin`、分箱样本数、类别权重、特征集合、输入精度或验证划分。
如果这些也同时改变，就难以解释本轮究竟比较了什么。

## 3. 参数逐个解释

### objective 与 metric：训练目标和监控指标不同

```python
"objective": "binary",  # 用二元分类损失计算梯度和 Hessian，训练树
"metric": "auc",        # 用 AUC 监控内部验证并选择配置、树数
```

`binary` 对应二元分类的 logistic 损失；这里 AUC 用于评价和选择，不直接用来计算树的梯度。
所以“按 AUC 选模型”与“训练时直接优化 AUC”是两件不同的事。
log loss 和 Brier 也用于折外评价，检查排序改善时概率质量是否同时改善。

### learning_rate：每棵新树贡献多少

LightGBM 每轮用一棵新树修正当前模型。概念上，先在原始分数空间更新：

```python
new_raw_score = old_raw_score + learning_rate * new_tree_output
p_repay = 1 / (1 + exp(-new_raw_score))
```

这是理解公式，不是本项目重新实现的训练代码。实际训练由原生 LightGBM 完成。
`0.05` 比 `0.08` 每轮走得小，通常需要更多树；步子更大可能更快，也可能越过好的解。
树数与学习率必须结合理解，不能说学习率越小越好。

### num_leaves：一棵树最多分成多少种情况

叶子是树最后给出预测贡献的位置。31 个叶子比 63 个叶子能表达的分区少。
更多叶子更容易学习复杂的非线性关系，也更容易记住局部噪声，并增加训练和预测成本。
LightGBM 采用优先分裂当前收益最大的叶子的生长方式；`max_depth=-1` 表示没有额外的
深度上限，不代表无限复杂，`num_leaves` 和叶子约束仍限制树。

### min_data_in_leaf：避免叶子只依靠少量样本

200 或 400 表示希望每个叶子有足够的样本支持。数值较大通常限制复杂度、减少噪声拟合，
但也可能忽略少量样本中的真实规律。LightGBM 的这个约束基于 Hessian 的近似，
并非保证每个叶子的实际样本数绝对不少于设定值。

### lambda_l2：约束叶子的预测贡献

可把 L2 正则化理解为给过大的叶子输出加惩罚。在二阶近似下，叶子输出与
`-sum_gradient / (sum_hessian + lambda_l2)` 有关。提高 L2 通常抑制过激的修正，
但太强会使模型学不充分。这与逻辑回归的系数惩罚目的相似，实现对象不同。

### feature_fraction：建树时抽取部分列

`0.8` 表示每棵树随机选大约 80% 的特征作为候选。全部 1,105 列仍在输入里；
这是每棵树的随机抽样，不是永久删除 20% 的列。它可以节省部分计算并增加树之间差异。

### bagging_fraction 与 bagging_freq：建树时抽取部分行

`bagging_fraction=0.8`、`bagging_freq=1` 表示每轮随机抽约 80% 的拟合行来建树。
如果 `bagging_freq=0`，这类行抽样不会启用。每轮抽样只在当前拟合数据内进行，
不会把早停数据或外层验证数据拿来训练。行抽样不等于整个实验只用 80% 的原数据。

### max_bin 与 bin_construct_sample_cnt：本轮固定的分箱设置

LightGBM 将连续值分成有限个区间，使用直方图加速分裂搜索。这里 `max_bin=63`，
用拟合数据中的 20,000 行抽样估计分箱边界。这个数相对全量数据较小，原生库会给出提示，
它是既有基线的资源折中，本轮固定使用；不能称为精度已最优的分箱方案。
20,000 是估计边界的样本量，模型训练仍使用相应阶段的全部拟合行。

## 4. 验证协议：参数应该在哪里选

已有五折固定不变。以第 0 折为例：

1. 第 0 折约 13.78 万条留作外层评价。
2. 其他四折约 55.12 万条按标签分层，85% 用于内部训练，15% 用于内部早停。
3. 四组候选都在约 46.85 万条内部训练数据上训练，在约 8.27 万条早停数据上选择树数。
4. 只比较内部早停 AUC，选出这一折的配置和树数。
5. 在完整的其余四折上从头重训，分别训练三个模型种子。
6. 最后预测第 0 折并计算折外指标。

对五折重复，所以每个原训练样本都恰好得到一次每种种子的折外预测。
这叫 OOF（out-of-fold）预测：预测它的模型训练时没有使用它。

```python
inner, stop, valid = base.split_outer_fit(labels, fold_id, fold, 0.15)
all_fit = np.flatnonzero(fold_id != fold)
```

`fold_id != fold` 得到“行是否不属于当前留出折”的布尔数组；`flatnonzero` 返回这些行的位置。
这些位置用于访问特征缓存，而不是拿业务 `id` 当输入特征。
划分函数只对其余四折分层抽样，随机状态为 `42 + fold`，不随模型种子改变。

本轮在每一折内选配置，不会先用五折 OOF 全局选一组参数，再把同一份 OOF 说成独立最终测试。
不同折可能选不同配置，五折模型平均是本轮训练流程的自然结果；
本轮没有训练一个使用全部 688,998 条数据的单一最终模型。

需要诚实说明：项目前几轮已反复使用这些外层折做开发决策，因此它们不是从未看过的最终测试集。
本轮的隔离解决“当前折外数据直接参与当前参数选择”的问题，不会消除历次开发决策带来的选择偏差。
真正的最终泛化结论仍需要新的保留集、可靠时间验证或官方测试成绩。

## 5. 早停代码在做什么

```python
selected = lgb.train(
    params, inner_data, num_boost_round=900,
    valid_sets=[stop_data], valid_names=["inner_early_stop"],
    callbacks=[
        lgb.early_stopping(60, first_metric_only=True, min_delta=0.0001),
        lgb.log_evaluation(100),
        lgb.record_evaluation(history),
    ],
)
```

`params` 是本组超参数，`inner_data` 是训练集，`stop_data` 只用于评价。
`num_boost_round=900` 是上限，不是每组一定训练 900 棵树。

`early_stopping(60, min_delta=0.0001)` 表示：AUC 必须比最近一次认可的最佳值高出
**超过** 0.0001 才算有效改善；连续 60 轮没有这种改善时停止。
`first_metric_only=True` 表示只监控第一个指标，这里只有 AUC。
`log_evaluation(100)` 只是每 100 轮打印一次；`record_evaluation(history)` 保存每轮 AUC。

`selected.best_iteration` 是按这个规则选出的轮数。由于 `min_delta` 的存在，
它不一定等于整个记录里数值最大的 AUC 所在轮数：极小的改善可能不算有效改善。
审计脚本逐轮重放该规则，核对选出的树数与记录一致。

如果用完 900 轮，本轮预算耗尽；不能说已经找到全局最优树数。
本轮不在看见折外结果后临时提高预算。

## 6. 候选怎么选，为什么不用微小差异决定一切

代码的选择逻辑可以概括为：

```python
best_auc = max(result["inner_auc"] for result in records)
eligible = result["inner_auc"] >= best_auc - 0.0001
# 按预先声明的候选顺序，选择第一组 eligible 的配置
```

`records` 是四组内部搜索结果。允许 0.0001 的差距，是预先设定的近似并列规则，
优先级为 `baseline_extended → regularized → wider → faster_rate`。
它不是统计显著性检验，0.0001 也不是置信区间。
不能在结果出来后改优先级去选想要的模型。

主要选择指标是还款 ROC-AUC。结果同时报告违约 AP、log loss 和 Brier，
防止排序提高、概率质量却下降的情况被隐藏。没有以准确率选模型：
这批数据约 91.67% 是还款样本，只预测还款也会有很高准确率。

## 7. 随机种子到底控制什么

种子可以理解成随机数序列的起点。固定种子能在同一运行环境中重复抽样过程，
不是把某个数字输入模型就获得更强的预测能力。

| 随机性 | 本轮规则 | 是否在种子实验中变化 |
|---|---|---|
| 外层五折划分 | 使用已有折表 | 否 |
| 内部训练/早停划分 | `42 + fold` | 否 |
| 估计分箱边界的行抽样 | `data_random_seed=42 + fold` | 否 |
| 每棵树的列抽样 | `feature_fraction_seed=seed + fold` | 是 |
| 每轮建树的行抽样 | `bagging_seed=seed + fold` | 是 |
| 模型通用种子 | `seed=seed + fold` | 是，但具体组件种子已显式指定 |

```python
params.update(
    seed=seed + fold,
    feature_fraction_seed=seed + fold,
    bagging_seed=seed + fold,
    data_random_seed=42 + fold,
)
```

模型种子提前指定为 **42、2026、3407**。例如 fold=2 时，建树实际种子分别是
44、2028、3409；分箱种子三者都是 44。数字本身没有业务意义。

三个种子使用同一折选出的配置和同一树数，不分别在外层数据上选树数。
这样主要观察行、列抽样引起的模型变化；不是三个种子各自最优训练时长的搜索。
对种子 42 选出的树数可能不完全适合其他种子，这是本轮控制变量的取舍。

`deterministic=True` 与 `force_col_wise=True` 帮助同环境复现。
不同 LightGBM 版本、编译方式、硬件或数值精度仍可能导致差异，不能保证到处逐位相同。
这里是 GBDT，模型保存以后，预测只是沿已经确定的树分支计算结果，不重新随机抽行或抽列；
推理时不需要再“挑一个更好的种子”。

## 8. 为什么不选最高分种子，而是平均概率

不同种子的预测可能略有不同。假设同一客户三个模型给出的还款概率是：

```python
p_seed_42 = 0.70
p_seed_2026 = 0.76
p_seed_3407 = 0.73
p_ensemble = (0.70 + 0.76 + 0.73) / 3  # 0.73
```

这叫概率平均，保留了风险程度信息。不是先用 0.5 把结果变成还款/违约，再做多数投票。
本项目使用原生 `lgb.Booster`，二分类 `model.predict()` 直接返回正类（还款）概率，
因此 `predict_rows` 得到的是概率数组，而不是 0/1 标签。
代码 `probability_mean` 会检查数组形状一致、没有 NaN/无穷、概率在 [0,1] 内，
然后 `np.stack(predictions).mean(axis=0)` 按客户逐行平均。

训练集 OOF：每一行平均的是三个都没见过这一行的同折模型。
测试集：每个种子先平均五折模型，再平均三个种子，等价于 15 个模型每个权重 1/15。
所有权重提前固定，没有用 OOF 去搜索最好的混合比例。

概率平均可能减少随机误差，但模型错误高度相关时提升有限，不保证 AUC 或 AP 上升。
在同一批样本上，等权概率平均的 log loss 和 Brier 根据凸性不会高于三模型对应损失的平均值，
却仍可能高于其中最好的单模型；排序指标没有这样的保证。
它也增加部署成本：需要保存、运行 15 个折模型，而单种子是 5 个。

## 9. 稳定性表应该怎么读

`seed_stability.csv` 每一折报告三个种子的 AUC 均值、最小值、最大值、样本标准差，
以及每个客户概率差异的平均大小、种子预测之间的相关性。

同折种子差异主要反映固定数据划分下的建树抽样随机性；不同折差异还包含验证样本组成
和拟合数据变化。两者不能混为一谈。
三个种子很少，不能把均值±标准差当作正式置信区间。
五折的训练数据也相互重叠，不是五次独立实验。

比较新旧模型时用 `paired_fold_metrics.csv`，在同一验证折上计算新旧 AUC 差值。
如果只某一折大幅提高、其他折下降，整体均值可能掩盖不稳定。
本轮保留每个种子全部结果，不只展示高分者。

## 10. 数据与内存方面的实现

仍使用原始 float32 缓存和内存映射；保留 NaN，不填补、不标准化，实际零值不当作缺失。
`IndexedSequence` 只复制当前读取的批次，并按 LightGBM 接口转换成 float64。
已有 float32 舍入造成的信息损失不会因为转换回 float64 而恢复。
`feature_51`、`feature_118` 在原始 DOUBLE 中的变化仍可能有意义，本轮没有验证恢复精度的收益。

每折四组候选共享一个内部训练 Dataset，早停 Dataset 使用 `reference=inner_data`，
因此共享同一分箱边界。分箱只依赖内部拟合行，外层验证、测试集不参与边界估计。
最终重训在完整拟合四折重新建立 Dataset，三个种子共享这个 Dataset。

```python
params["feature_pre_filter"] = False
```

这是重要的工程细节。LightGBM 构造 Dataset 时可能依据当时的 `min_data_in_leaf`
预先忽略某些无法分裂的特征。我们要在同一个 Dataset 上比较不同的叶子样本约束，
所以关闭这一层预过滤，避免之前的候选影响后面的候选。它不表示使用全部特征做每次分裂，
`feature_fraction` 仍然生效；也不是人工特征筛选。

内存映射和分批读取不等于零内存训练。LightGBM 仍要保存分箱数据和直方图。
`histogram_pool_size=128` 控制直方图缓存，4 线程控制 CPU 使用。
可用两个独立本地进程处理互不重复的折；没有启动子代理。

## 11. 主程序和产物怎么对应

| 函数 | 作用 |
|---|---|
| `params_for` | 合并固定基线、候选参数和组件种子 |
| `choose_candidate` | 只根据内部 AUC 与预声明并列规则选配置 |
| `probability_mean` | 检查概率后逐行等权平均 |
| `load_context` | 校验 id、标签、固定折号，复用原始特征缓存 |
| `initialize` | 将候选、种子、数据来源、代码校验值写入不可随意变更的实验配置 |
| `checked_config` | 确认恢复运行时数据、代码、基线、版本均一致 |
| `checkpoint_record` | 核对已经完成模型和预测文件的 SHA256 后复用 |
| `run_fold` | 当前折的四组内部搜索、三个种子完整四折重训 |
| `collect` | 汇总完整 OOF、测试预测、指标、稳定性和提交文件 |

`inner_models` 保存用于内部选择的 20 个模型；`models` 保存真正生成 OOF/测试预测的
15 个完整四折重训模型。内部模型不是最终提交模型。
`inner_curves` 保存逐轮 AUC；`selections` 保存每折为什么选择某组配置。
`oof_predictions.parquet` 保存 id、标签、折号、压力标记、三种子概率及集成概率。
`test_predictions.parquet` 只有测试 id 和预测，没有借用训练标签。
`id` 始终用于对齐，不能因为训练和测试 id 数值重叠就连接标签。

保存训练签名可阻止把旧代码、旧数据的完成折混入新实验。未完成的单个模型会从头训练，
不是继续接着某棵树训练。已有完成模型自动复用，不需要另加 `--resume`。

```powershell
.\.venv\Scripts\python.exe scripts/report_hyperparameter_seed_optimization.py
```

单进程 `--stage train` 会顺序处理五折。若有足够内存，可开两个终端，
分别在 `--stage train` 后加 `--folds 0 2 4` 和 `--folds 1 3`。
不能让两个进程处理同一折，以免同时写同一 checkpoint；所有折完成后才 `collect`。
初始化已存在且签名一致时只校验并复用，不覆盖成果；参数或代码变了则拒绝混用。
`max-rounds`、`patience`、`threads`、`batch-rows` 在 `init` 阶段设定；
`train`、`collect` 从已签名的 `run_config.json` 读取设置，不能临时通过训练阶段改动实验预算。

训练期间可在另一个终端运行下面的只读命令查看进度，它不加载原始特征缓存，也不重新训练：

```powershell
.\.venv\Scripts\python.exe scripts/show_hyperparameter_seed_progress.py
```

只有某一折三个种子都完成，才显示该折集成分数，并明确标为部分结果。
五折全部完成之前，不能把已完成折的平均或拼接分数当作全量 OOF 成绩。

## 13. 如何决定本轮开发模型

预先设定的保守规则：三种子集成相对原基线 AUC 至少提高 0.0005，
违约 AP 下降不超过 0.001，log loss 增加不超过 0.0005，才推荐作为下一步开发候选；
否则保留原基线。这里的容忍量是工程选择，不是统计显著性或业务审批标准。
选择发生在开发 OOF 上，所以仍属于开发决策。
不会因为一个单独种子分数更高就临时改成该种子。

两个先前声明的压力组仍分别计算指标，样本相互重叠，不能相加当总量。
AP 依赖违约率，应同时看每组的基准违约率。
测试 `feature_492` 大量值超出训练范围；这里没有这些测试样本的标签，
本轮的随机五折分数和压力组分数都不能证明这种漂移已被解决。

## 14. 面试问题与可以诚实使用的回答

**你调了哪些参数，为什么？**

我固定特征和数据划分，预先比较四组 LightGBM 配置，覆盖学习率、叶子数、叶子样本约束、
L2 正则、行列抽样比例。它们分别影响学习速度、模型复杂度和随机性，
每折只在拟合数据内部选配置和早停树数。这是小规模联合候选搜索，没有宣称找到全局最优。

**怎么防止调参时数据泄漏？**

外层留出一折，其余四折再分内部训练和早停。候选的分箱、拟合和选择都不使用留出折。
选择后在完整拟合四折从头重训，再预测留出折。测试集不参与训练、早停或标签关联。
我还写了隔离测试，修改留出折的特征和标签后，拟合模型的预测保持一致。
这些折已用于多轮开发，所以我会把结果称为开发验证分数，另留最终测试验证泛化。

**为什么不同折选不同参数？**

每折拟合数据和内部验证样本不一样，最合适的候选可能不同。
我评价的是“内部选择再训练”的完整流程，输出是这些折模型的平均，
没有用全部折外标签挑一组统一配置然后称其分数是独立评价。

**你是否挑了最高分的随机种子？**

没有。我提前固定三个种子，保留完整结果，固定划分、分箱、参数和树数，只改变建树行列抽样。
最终使用等权平均概率。挑最高分种子容易利用验证噪声，无法保证新数据上还是最高。

**为什么平均有帮助，代价是什么？**

不同抽样训练出来的模型有一些不同误差，平均概率可能降低方差，效果取决于错误的相关性。
本轮测试预测平均 15 个折模型，训练和推理成本更高，排序分数也不保证提高。

**你用了 Optuna 吗？**

本轮没有。机器资源有限，我先用四组可解释的候选跑完整的折内选择与种子实验，
保证可复现和结果可比较。进一步可以在同样的内部选择协议下使用 Optuna，
但仍应固定预算、记录试验，并保留最终评价数据。

**AUC 提高就说明模型更好吗？**

AUC 衡量排序，不代表概率准确或业务收益。我还比较违约 AP、log loss、Brier 和逐折结果。
业务部署还需要可靠的最终验证、概率校准、阈值成本分析及漂移监控；本轮没有完成这些步骤。

**简历怎么写？**

可以根据本轮真实结果写：在约 69 万条贷款样本、1,105 个匿名特征上，实现 LightGBM
五折框架下的折内超参数选择与三种子等权概率集成，将开发 OOF AUC 从 **0.816569**
提升至 **0.820395**，违约 AP 从 **0.388912** 提升至 **0.395367**；完成 35 个模型的
训练与重载审计，五个验证折的集成 AUC 均改善。

这段数字描述的是参数选择、增加训练预算/早停耐心和概率集成共同作用下的开发验证
结果，不能把全部收益归因于某一个参数。不要写官方获奖、生产部署、全局最优参数或
解决时间漂移，除非之后实际完成并有证据。
