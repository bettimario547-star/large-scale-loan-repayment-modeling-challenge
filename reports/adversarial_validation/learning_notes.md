# 对抗验证学习笔记：训练集与测试集是否来自相似分布？

这一步回答的是“能否只看特征，就判断一条记录来自官方训练集还是官方测试集？”
它**不**预测贷款是否还款。完整可运行代码在
`scripts/run_adversarial_validation.py`；具体数值和图见同目录的
`adversarial_validation_report.md`、`adversarial_validation.png`。

## 1. 重新定义一个临时标签

```python
domain_label = np.concatenate([
    np.zeros(sample_per_source, dtype=np.uint8),  # 官方训练集
    np.ones(sample_per_source, dtype=np.uint8),   # 官方测试集
])
```

原竞赛的 `label` 是还款目标；这里的 `domain_label` 是数据来源目标。若一个模型
在没见过的记录上也能准确识别来源，说明两组特征的联合分布有差异。
`id` 只用于固定抽样，不喂给模型；`label` 在测试集不存在，也绝不能作为来源特征。

## 2. 为什么抽取等量样本

官方训练集有 688,998 行，测试集有 36,324 行。脚本用 DuckDB 的
`ORDER BY hash(id, 20261018) LIMIT 36324` 固定抽取训练样本，再与全部测试样本比较。
这样来源类别各占一半，模型不会通过“全猜训练集”取得高准确率，而且计算量适合本机。
固定哈希和随机种子保证复现。**AUC 本身不要求类别平衡**；平衡主要是为训练和实验设计服务。

局限：这里只检查了训练集的一个固定样本；以后若结果需要更稳健，可换几个种子重跑。
不能把这里的训练样本当作“时间更接近测试集”的样本，因为尚未证明 `id` 代表时间。

## 3. 三折验证与早停各负责什么

```python
folds = StratifiedKFold(n_splits=3, shuffle=True, random_state=SEED)
for fit_index, valid_index in folds.split(X, domain_label):
    inner_fit_index, early_stop_index = train_test_split(
        fit_index, test_size=0.15,
        stratify=domain_label[fit_index], random_state=SEED,
    )
    model.fit(X[inner_fit_index], domain_label[inner_fit_index],
              eval_X=X[early_stop_index], eval_y=domain_label[early_stop_index],
              callbacks=[lgb.early_stopping(30, verbose=False)])
    score = model.predict_proba(X[valid_index])[:, 1]
```

上面是说明性摘录；实际脚本的每折随机种子略有不同。外层每折约三分之二用于
“拟合 + 早停”，其余三分之一只用于最终 AUC。早停会选树的数量，因此不能同时
拿外层验证折早停、再把该折当完全独立的最终评价。分层保证每折都有相近的
训练/测试来源比例。三折使用相同划分来比较不同方案，是为了减少“划分不同”
造成的比较噪声。

## 4. 为什么要做三种方案

| 方案 | 输入 | 想排查的问题 |
| --- | --- | --- |
| 全部数值 | 1,105 个匿名特征；NaN 保留 | 总体来源可分性有多强？ |
| 删除测试集全空列 | 去掉 7 列，剩 1,098 列 | 是否仅靠这 7 列就能识别来源？ |
| 仅缺失指示器 | 对剩余列做 `np.isnan(X).astype(np.uint8)` | 不看数值，仅看“哪里缺失”还能区分吗？ |

LightGBM 能直接处理 NaN，所以不需要先用平均值填补。第三种方案把每个特征改成
“缺失为 1、非缺失为 0”，用于隔离缺失模式的贡献。它删除了那 7 个测试集全空列，
因此结果不是被这 7 个最显眼的缺失差异单独撑起来的。

## 5. 怎样读 AUC 和特征重要性

`roc_auc_score(y_true, score)` 衡量随机抽一条测试来源记录和一条训练来源记录时，
模型把前者排在更高“来自测试集”概率的机会。0.5 约等于随机猜测，1.0 是完全
可分。这个 AUC **不能写成贷款还款预测 AUC**。

本次三个方案的均值分别约为 **0.99999868、0.99999854、0.975405**。
前两个值非常接近，但不等于精确的 1。去掉 7 列后仍几乎完全可分，说明差异不只
存在于这 7 列。仅缺失指示器也能达到 0.975，说明缺失位置本身携带很强的来源信息。

`feature_importance.csv` 的 `mean_gain_share` 是三折 LightGBM 分裂增益占比的
平均值，表示该特征在“识别来源”这个模型中的作用。它**不是**还款预测的重要性，
也不是因果效应。高度相关的特征能互相替代，所以不能按此排名直接删除特征。
报告中的 PSI 只比较各列的非缺失数值分布；缺失率变化在相邻两列单独展示。

最强的 `feature_492` 可做不依赖模型的核查：只用该列原始数值排序，AUC 约 0.997。
测试样本有约 76.5% 的非缺失值高于**全量训练集**的最大值。对匿名列，我们可以说它有
强烈的范围变化，但不能擅自声称它就是时间、利率或某个业务字段。
这一列还提示“训练数据覆盖不到部分测试范围”：给训练样本重新加权也不能凭空
制造该范围内有还款标签的样本，所以不能把对抗验证直接当成修复办法。

## 6. 对下一步还款模型的影响

对抗验证是**诊断工具，不是修复方案**。分布差异意味着普通随机切分可能无法充分
模拟官方测试集，尤其竞赛说明测试集发生在训练集之后；但本实验本身不能量化
随机验证会乐观多少，更不能保证某一种新切分一定更准。下一步应检查训练数据
是否有可信的时间顺序线索，在证据充分时比较“随机分层验证”和“靠后留出验证”；
再用还款标签做消融实验，检验高漂移特征的真实价值。官方测试集特征只用于本次
无监督分布诊断，不用于训练还款模型或计算其填充值。

## 面试时可以这样讲

> 我把训练/测试来源构造成一个新的二分类问题，等量抽样后用三折分层验证训练
> LightGBM。全特征来源 AUC 接近 0.999999；去除测试集全空的 7 列后仍接近
> 0.999999；只看缺失位置也有约 0.975。进一步核查发现，`feature_492` 单独
> 就有约 0.997 的来源 AUC，说明确实存在强烈的数值分布变化。这个结果不能
> 当作还款模型表现，也不能直接据此删除特征。我会把随机验证作为基线，再验证
> 是否能构造更接近未来数据的切分，并通过还款模型消融实验判断高漂移特征价值。
