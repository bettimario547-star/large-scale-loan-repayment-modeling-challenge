# 对抗验证：识别训练集与测试集漂移

## 目标与方法

把数据来源作为一个新的二分类目标：`0 = 原训练集`，`1 = 原测试集`。
它与贷款还款标签 `label` 是两个不同的目标。若两组数据无法区分，ROC-AUC 接近
0.5；若 AUC 明显高于 0.5，说明模型能利用特征识别数据来源，存在分布差异。

用 `hash(id, 20261018)` 从 688,998 条原训练样本中固定抽取 36,324 条，
与 36,324 条测试样本组成平衡数据集。`id` 只用于抽样，不输入模型；
`label` 也不输入模型。所有特征在 DuckDB 中转为 `float32`，缺失值保持为 NaN。
采用 3 折分层交叉验证，各方案使用相同的折划分。每折再从拟合部分切出
15% 用于 LightGBM 早停，外层验证折只用于最终 AUC 评价。

## 结果

| 方案 | 各折 ROC-AUC | 均值 | 折间标准差 |
| --- | --- | --- | --- |
| all_values | 0.99999865, 0.99999806, 0.99999934 | 0.99999868 | 0.00000064 |
| exclude_test_all_null | 0.99999875, 0.99999730, 0.99999956 | 0.99999854 | 0.00000114 |
| missing_mask_only | 0.97530590, 0.97568064, 0.97522844 | 0.97540499 | 0.00024183 |

- 全特征 AUC：**0.99999868**。
- 去除测试集全空 7 列后 AUC：**0.99999854**。
- 仅用“是否缺失”指示器的 AUC：**0.97540499**。
- 全特征与去除 7 列的 AUC 差：**+0.00000015**。

去掉测试集全空的 7 列后仍几乎能完全区分来源，说明还存在其他强烈的分布差异。缺失指示器模型说明仅凭“哪些位置为空”也能很好地区分来源；
它的 AUC **不是贷款还款预测的 AUC**。这些结果证明存在分布差异，不能仅凭对抗验证
断言差异完全由时间造成，也不能推算其对还款模型成绩的影响大小。

测试集全空的 7 列是：`feature_364`, `feature_614`, `feature_648`, `feature_660`, `feature_805`, `feature_1009`, `feature_1031`。

### 单特征核查

最重要的 `feature_492` 不经模型训练、只按原始值大小排序（排除该列缺失行），
区分来源的 AUC 就达到 **0.997109**。
等量样本中，训练/测试的该列中位数分别为
**8.1146 / 8.8670**；
全量训练集最大值为 **8.8416**，而测试非缺失样本中
**76.5%** 超过它。
这是直接在原始特征分布上看到的差异，支持对抗模型的高 AUC 并非单纯的模型评价错误。
但特征匿名，不能仅凭数值给它命名为“时间”。

## 对后续建模的含义

1. Kaggle 页面说明测试集晚于训练集；本次结果量化了训练/测试分布变化。随机分层
   划分仍可作为初始基线，但它可能高估对未来贷款的泛化能力。
2. 下一步检查训练集原始行序是否有时间信号。如果有，再设计靠后的留出集或滚动验证，
   并把这种验证结果与随机分层结果并排比较。
3. 将高漂移特征作为消融实验的候选，不按对抗验证 gain 排名直接删除；它们可能同时
   含有真实的违约预测信息。
4. 测试集全空的 7 列无法在最终预测时提供数值，可在还款模型中比较“保留”与“删除”
   两种方案。
5. 本项目不把测试集原始特征用于估计填充值、监督特征筛选或还款模型训练。

## 代码怎么复现

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe .\scripts\run_adversarial_validation.py
```

脚本会在 `reports/adversarial_validation/` 生成折指标、特征重要性、图和本报告。
