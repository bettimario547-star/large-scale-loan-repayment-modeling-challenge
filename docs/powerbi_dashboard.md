## 在 Desktop 中打开

1. 启动已安装的 Power BI Desktop，选择“文件 → 打开 → 浏览”，打开 `dashboard/powerbi/LoanRisk.pbip`。保留同级 Report、SemanticModel 和 data 文件夹。双击入口也可使用已注册的文件关联。
2. 使用支持 PBIP 和 PBIR 的 Desktop 版本。若当前版本仍将项目/PBIR 列为预览功能，在“选项和设置 → 选项 → 预览功能”启用相应项并按提示重启；选项名可能随版本变化。若无法识别入口，先查看是否为旧版本或是否仅下载了安装包。
3. 点击“刷新”。语义模型首次打开没有缓存，需要从本地 CSV 导入数据。Power Query 使用 UTF-8、逗号分隔和 `en-US` 数值格式，先将数字空字符串转为 `null`，再转换类型。
4. 如果移动过项目，在“转换数据 → 管理参数”把 `DataFolder` 改为新的 `dashboard/powerbi/data` **绝对路径**，关闭并应用后再刷新。此处是文本参数，不是源文件逐一修改。
5. 确认底部六页导航出现。切片器选中唯一值时使用所选假设；清除选择后回到度量默认值。模型默认同时比较两者，可单选和清除；没有使用跨页同步切片器。
6. 完成下方验收后保存项目。如需单文件分享，可在 Desktop 中“另存为” `.pbix`。本项目无需 Power BI Service 登录、工作区发布或数据上传。

## 三类证据不能混用

| 分类 | 可展示的内容 | 解释边界 |
| --- | --- | --- |
| 历史结果 | 历史标签、复用 OOF 排序指标、历史审批结果、测试分数构成 | 开发数据已经参与模型/方案迭代，不是新独立未来检验；测试无标签 |
| 模拟假设及分析 | 本金/利息/LGD/成本、收益、A/A 误报、独立组离线演练、合成备择、假设周期 | 历史标签与假设现金流组合；不等于真实线上因果收益或后验概率 |
| 真实业务待验证 | 去重、安全准入、真实分流执行、成熟现金流、DPD、未来流量及分歧构成 | 缺少实际观测；NULL 表示未知，不代表零收益、零违约或护栏通过 |

数据没有收入、年龄、地区等可解释字段，不虚构匿名特征的业务含义。还款分数是未校准的模型分数，不能直接当作真实未来违约概率。

### V2 收益及晋级

V2 在审批分歧人群中分层随机分流，以冻结的完整共同合格权重还原 ITT。共同合格评价目标为 210,856 个申请，实际随机分歧样本为 12,614；规划需要 17,141。原独立全合格方案规划 3,721,531 个随机样本，这些样本量对应不同随机范围。

| 晋级条件 | 当前冻结证据 | 判断 |
| --- | --- | --- |
| 每完整共同合格申请净收益增量的 95% 下界 > 5 元 | 点估计 +3.672403 元；95% 区间 [0.119257, 7.225548] 元 | 未达到；零差 p≈0.0428 不能替代业务门槛 |
| ITT 违约差单侧上界 < +0.2000 个百分点 | 上界 −0.0044 个百分点；差 −0.0430 个百分点 | 离线通过 |
| 审批率差 > −2.0000 个百分点 | 差 −0.0408 个百分点 | 离线通过；审批规则历史对比 |
| 完整 B 批准组合违约上界 <= 5% | 上界 3.2222% | 离线通过 |
| 匹配校准与分流质量 | 20/20 认证，当前质量通过 | 限定离线范围内通过 |
| 固定样本和每层每组最低数量 | 12,614 / 17,141；每层每组要求 >=100 | 总样本未达到 |
| 真实结果成熟 | 未取得真实现金流/DPD 完结数据 | 待验证 |
| 真实业务安全与去重 | 仅有代理准入，缺持久 borrower_id | 待验证 |

当前决定来自冻结审计的 `ProductionReady=0`。度量使用 `REMOVEFILTERS()`，用户筛掉某个失败门槛不能让决定变成晋级。编辑者可以修改源代码，因此这是报表解释约束，不是访问控制或安全边界。

### A/A 与 A/B 能力解释

原 A/A 必检场景通过，1 万申请、B 组 10% 的压力场景中收益误报率约 5.536%，六个端点/α组合未认证。V2 匹配校准包含 18 项同 Champion 零差检查和两项业务/非劣效边界检查，20 项均认证；32 次实际哈希抽查与大量统计模拟承担不同验证作用。当前报表不把有限历史总体/IID 认证扩张为未来真实业务安全。

未经调整的五次查看演示：固定终点双侧误报 4.934%，任一次显著即停止 14.20%。这个演示终点是 100,000 申请，不是正式原方案的 372 万终点。正式流程维持固定样本分析；安全停止与效果停止应分别治理。

规划样本下，历史经验模拟的联合成功频率约 0.55%；合成真实增益 +10 元备择约 90.53%。前者是固定历史经验/IID 条件下的演练，后者是人为设定效应后的设计能力检验；二者都不是 Challenger 真收益超过门槛的后验概率。

## 周期控件与暴露

每日申请量可选 1,000 / 5,000 / 20,000；共同合格占比可选 20% / 75%；分歧入组比例可选 50% / 100%。这些表与结果事实表断开关系，周期度量读取选择后计算：

```text
日均分歧入组 = 每日申请量 × 合格占比 × 冻结分歧占比 × 分歧入组比例
入组天数 = ceil(17,141 / 日均分歧入组)
最终分析天数 = 入组天数 + 假设成熟 365 天 + 宽限 30 天
```

默认完整分歧入组为 289 天入组、684 天最终分析；50% 分歧入组为 577 天入组、972 天最终分析，超出 365 天入组约束。这里的“可行”只指入组天数，不表示 684 天已经获准或能够接受，也未考虑季节性、渠道漂移、每日不均匀到达和结果缺失。

V2 通过减少一致审批决策的随机噪声，提高回答完整合格人群 ITT 业务问题的效率。但分歧全量入组使审批改变暴露约为原方案两倍，仍需真实安全审核。75% 合格覆盖率是备选流量假设，不能替代真实安全准入评估。

## 真实实施与维护

真实实施还需持久借款人 ID 和首申请去重、预分流完整人群与分数、安全准入、pilot/main 与分流概率、模型/阈值版本和实际审批日志、真实本金/利息/核销/回收及成本、到期/完结日期和 DPD30/60/90、结果完整性与未来流量/分歧构成。应先 shadow 核对这些数据，再独立 pilot，随后锁定主实验固定样本及停止规则。需要重新生成独立版本的证据，不能用当前仪表盘控件虚构新实验结果。

`source_manifest.json` 记录源报告和聚合 CSV 的 SHA-256；`data_dictionary.json` 记录表列、类型及空值数量；`measures.dax` 便于审阅度量；`artifact_verification.json` 明确文件级验证范围。原冻结报告未修改，生成器不训练模型。
