# `id` 的角色与真实数据核查

## 结论

`id` 是**各文件内部的记录键**，不是贷款的业务特征，也不是时间。模型输入严格为
`feature_1` 到 `feature_1105`（共 1,105 列）。`label` 是训练目标；
`fold` 和压力组标记是验证元数据，也不能进入模型。

| 数据 | 行数 | 非空且唯一的 id | id 范围 |
|---|---:|---|---|
| 训练集 | 688,998 | 是 | 0–688997 |
| 测试集 | 36,324 | 是 | 0–36323 |
| 官方提交模板 | 36,324 | 是 | 0–36323 |
| 五折表 | 688,998 | 是 | 0–688997 |

训练和测试共有 36,324 个相同的 **id 数字**。这是因为测试集
也从 0 编号；**不能**把两个文件里的同号记录视为同一笔贷款，或通过 id 把
训练标签接到测试集。这里的 `id` 只有在明确指定数据集的语境下才有意义。

测试集对模板的反连接剩余 0 行；模板对测试集剩余
0 行，说明两边的 id 集合严格一致。模板的正式列名
是 `id,prediction`，其中 `prediction` 应填模型预测的 `label=1` 还款概率；
模板中的 0.5 只是占位值。

训练集对五折表的反连接剩余 0 行；五折表对训练集剩余
0 行。折号仅有 0–4，计数为 {0: 137800, 1: 137800, 2: 137800, 3: 137799, 4: 137799}。
使用五折表时应该用训练集 `id` 做一对一关联，再从关联结果中取 `fold`；
不能默认两张表第 N 行属于同一条记录。

本次仅检查数据契约，**没有训练还款模型，也没有生成真实 Kaggle 提交或还款 AUC**。
