# 第二步：确定验证策略并检查漂移稳健性

## 本次决策

上一项“训练集行顺序”分析没有找到可信的时间轴。因此**现在不做伪时间验证**：
不能把文件最后 20% 直接叫作“未来贷款”。本阶段建立可复现的**五折分层
交叉验证**，同时检查这种随机验证与官方测试集到底有多不像。
完整实现是 `scripts/build_validation_strategy.py`，输出报告是
`reports/validation_strategy/validation_strategy_report.md`。

这里尚未训练还款模型，所以没有所谓“本次还款 AUC”。这一步解决的是
“以后该怎样公平地评估模型”，不是“现在模型有多好”。

## 1. 什么是一折？为什么要分层？

训练集有 688,998 条记录，其中约 8.33% 是违约（`label=0`）、91.67% 是
还款（`label=1`）。五折交叉验证把每条记录分配到一个 `fold`：

- 第 0 次：fold 0 当验证集，fold 1–4 当拟合集；
- 第 1 次：fold 1 当验证集，其余四折拟合；
- 如此直到 fold 4。每条记录恰好被验证一次。

核心代码：

```python
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
fold_id = np.full(len(labels), -1, dtype=np.int8)
for fold, (_, valid_index) in enumerate(cv.split(np.zeros(len(labels)), labels)):
    fold_id[valid_index] = fold
```

`Stratified` 表示每一折尽量保留原来的还款/违约比例；`shuffle=True` 是因为
训练文件行号没有被验证为时间；`random_state=42` 让划分可复现。`np.zeros(...)`
只是给 `split` 提供一个占位的 X：**折号只由还款标签和随机种子决定，不用匿名
特征或测试数据决定**。这不是用还款标签训练模型，而是在建立标签比例平衡的
验证集。

真实结果：五折验证集各有约 137,800 条记录，每折违约约 11,480 条；
五折的还款率都约为 91.669%，与全量训练集 91.6692% 几乎一致。

## 2. 为什么要把折号保存下来？

脚本把 `id`、`fold` 和两个压力分组标记写入
`data/interim/validation_folds.parquet`。以后逻辑回归、LightGBM、CatBoost
等模型都使用同一组验证折，才可以公平比较分数；不能因为换一次随机种子
使某个模型的验证集恰好更容易，就误以为模型变好了。

折号保存前会检查每条训练记录只出现一次。再次运行脚本时，若现有折表
与新生成的不同，脚本会报错，而不会悄悄覆盖验证协议。

以后训练时应这样使用折号，`id` 只负责对齐，**不是模型特征**：

```python
folds = pd.read_parquet("data/interim/validation_folds.parquet")
fold_id = folds.sort_values("id")["fold"].to_numpy()

for k in range(5):
    fit_index = np.flatnonzero(fold_id != k)
    valid_index = np.flatnonzero(fold_id == k)
    # 只用 fit_index 拟合预处理器、特征变换和还款模型。
    # 只在 valid_index 上生成该折的折外预测。
```

这里假设特征矩阵也按 `id` 排序。若实际行序不同，要先按 `id` 显式连接，
不能直接拿两个表的第 N 行对应。

## 3. KS 距离是怎样检查漂移的？

KS 距离比较两个样本的数值分布，范围从 0 到 1；越大越不像。
脚本对无监督筛出的重点特征做两种比较：

1. 每折的“拟合四折 vs 验证一折”；
2. “全部训练集 vs 官方测试集”。

例如 `feature_492`：五次折内比较最大的 KS 只有 **0.003**，而全部训练集与
官方测试集的 KS 是 **0.955**。这说明随机验证折确实很像训练集的其他部分，
却**远不像官方测试集**。所以分层交叉验证能提供稳定的训练内基线，不能自动
保证 Kaggle 测试成绩也一样。

KS 只比较**非缺失数值**。缺失模式必须分开检查：`feature_1039` 在最极端的
折内缺失率差仅 **0.14 个百分点**，训练/测试之间却差 **80.37 个百分点**。
报告分别展示 KS 和缺失率差，避免把“测试集全部缺失、无法算数值 KS”误写
成“没有漂移”。

## 4. 什么是压力分组？为什么阈值要从拟合集计算？

整体 AUC 可能掩盖某类数据表现很差。我们预先标记两种测试集分布有明显变化的
训练样本，留给下一步模型训练后做**分组评价**：

- `stress_feature_492_upper_tail`：该折验证集中，`feature_492` 高于或等于
  **该折拟合四折**第 90 百分位的记录；
- `stress_feature_1039_observed`：`feature_1039` 非缺失的记录。测试集中这种
  状态更常见，而训练集中较少见。

第一类的阈值只用拟合部分计算，代码逻辑是：

```python
fit = fold_id != k
valid = fold_id == k
cutoff = np.nanquantile(feature_492[fit], 0.90)
upper_tail[valid] = feature_492[valid] >= cutoff
```

这样保持验证折独立，不让验证折或测试集参与确定该折的参考阈值。每折的
高尾组有约 14,000 行、至少 1,324 条违约；`feature_1039` 非缺失组有约
24,500 行、至少 2,288 条违约。以后有**折外还款概率**后，才能计算这些组的
还款 ROC-AUC、违约 PR-AUC 等性能指标。目前只完成分组、样本量和分布检查，
**没有宣称模型在这些组上表现好或坏**。

## 5. 为什么压力分组仍不能解决全部问题？

约 **76.5%** 的测试集非缺失 `feature_492` 值，超过了全量训练集在这一列的
最大值。训练集中没有这些取值对应的还款标签，所以任何训练内验证——包括
高尾组——都不能直接告诉我们模型在那部分测试样本上的真实表现。简单地给
训练样本加权，也无法凭空制造训练集中不存在的带标签样本。

这就是当前验证策略的诚实边界：五折是必要的可复现基线，加上分布与分组
压力检查可以及时发现风险，但它不能模拟未知的未来分布。若以后取得可信的
放款日期、批次或其他顺序字段，应重建时间留出或滚动验证，不能沿用现在的
文件行号冒充时间。

## 下一步真正训练模型时的检查表

1. 使用保存的同一套折号，记录每折还款 ROC-AUC 和整体折外 AUC。
2. 从 `default_flag = 1 - label` 和 `p_default = 1 - p_repay` 计算违约 PR-AUC。
3. 用**折外预测**分别检查两个压力组的分数和样本数，再与整体分数比较。
4. 若模型需要早停，从拟合四折内部另切早停集，外层验证折只用于最终评价。
5. 不因单次 public leaderboard 或某个压力组分数上涨而反复修改验证规则。
